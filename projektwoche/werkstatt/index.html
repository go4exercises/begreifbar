Ebene 1Mein Weg: vom Chat zur eigenen Website

Ich bin Lehrer, nicht Informatiker. Programmiert hat die KI (Claude von Anthropic). Meine Arbeit war es, zu sagen, was ich will, das Ergebnis zu prüfen und die Abmachungen aufzuschreiben. Gebaut habe ich in kleinen Schritten, über fünf Monate.

  1. Mai 2026 Im Chat, mit ZIP-Dateien

    Die ersten Mathe-Seiten entstanden im Chat auf claude.ai. Jede neue Fassung kam als ZIP-Datei, die ich auspackte und auf GitHub hochlud. Am 5. Mai war die erste Fassung online.

    Für den Anfang reicht das. Bei vielen Seiten wird es aber mühsam: Das ganze Projekt geht bei jeder Änderung hin und her, und der Chat vergisst die Abmachungen des letzten Mals.

  2. Juni 2026 Umzug in die Werkstatt: Ubuntu, Claude Code, Git

    Am 15. Juni ging Physik online, eine Woche später zog das Projekt auf meinen Laptop um. Dort läuft Ubuntu unter Windows. Claude Code arbeitet im Terminal direkt in meinen Dateien, und Git merkt sich jede Änderung. Mathe folgte mit derselben Einrichtung.

    Ein Rückgängig-Knopf für das ganze Projekt (Git) macht mutig. Ich konnte ausprobieren, weil ich jeden Schritt zurücknehmen konnte.

  3. Juni bis Juli 2026 Regeln, Skripte, ein gemeinsames Aussehen

    Was ich der KI mehr als zweimal sagen musste, schrieb ich in eine Datei CLAUDE.md, eine Hausordnung, die Claude bei jedem Start liest. Das Aussehen steht in einer einzigen style.css. Ein Prüfskript, der «Pre-Flight», kontrolliert vor jedem Speichern Links, Formeln und Animationen.

    Die KI ist nur so verlässlich wie die Regeln, die sie bekommt. Gute Regeln sind kurz und konkret: «Knöpfe mindestens 44 px hoch», nicht «schön gestalten».

  4. 10. August 2026 Eine eigene Adresse

    Statt go4exercises.github.io/… heissen die Seiten jetzt mathe.begreifbar.ch und physik.begreifbar.ch. GitHub Pages liefert sie gratis aus, nur die Domain kostet etwas.

  5. 30. August 2026 Vertonte, animierte Clips

    Ein Clip ist kein Video, sondern eine kleine Webseite, die einen Gedankengang Zeile für Zeile aufbaut. Von Hand schreibe ich nur das Drehbuch. Ein Skript macht daraus die Animation, und die Stimme spricht ein Programm namens Piper. Es läuft auf dem Laptop, ganz ohne Internet.

  6. ab 31. August 2026 Leitprogramme

    Zum Selberlernen: ein Thema in kleinen Schritten, mit Clips, Erkundungen und Fragen mit Rückmeldung. Das erste war «Potenzen» in Mathe, dann «Ideale Gase» in Physik.

  7. Oktober 2026 Simulationen, Werkzeuge, Sek I

    Grössere Simulationen und Trainer bekommen eigene Seiten, und Sek1-Mathe kommt dazu. Heute stecken über 1000 gespeicherte Arbeitsschritte (Commits) in den Projekten.

Wer genau hinschauen will Alles ist öffentlich: die Hausordnung CLAUDE.md, der Styleguide, die Anleitung für die Clips und die ganze Geschichte unter Commits.

Ebene 2Dein Weg: Welcher passt zu deiner Idee?

Du musst meinen Weg nicht nachgehen. Für die meisten Ideen reicht der erste.

Ebene 3 · Weg AEine Datei mit der Claude-App

Du brauchst ein Konto auf claude.ai. Im Browser geht alles; die Desktop-App für Windows und Mac kann zusätzlich Dateien direkt auf deinem Computer ablegen (Schritt A6).

A1Die Idee in einem Satz5 min

Bevor du etwas tippst, beantworte drei Fragen auf Papier:

  1. Was soll es tun? «Ein Trainer, der mir Einheiten-Umrechnungen stellt.»
  2. Für wen? «Für mich und meine Klasse, BM1, vor der Prüfung.»
  3. Wann ist es gut? «Wenn ich zehn Aufgaben lösen kann und am Ende sehe, was ich falsch hatte.»

Der dritte Satz ist der wichtigste. Mit ihm prüfst du nachher, ob das Ergebnis taugt.

A2Der erste Auftrag: eine Vorlage zum Kopieren5 min

Kopiere die Vorlage, die zu deiner Idee passt, in den Chat und ersetze alles in ⟪…⟫. Der letzte Absatz ist bei allen gleich, er macht aus dem Ergebnis eine Datei, die überall läuft.

Präsentation 
Erstelle eine Präsentation als einzelne HTML-Datei zum Thema ⟪Thema⟫ für ⟪Publikum⟫, ⟪8⟫ Folien. Blättern mit den Pfeiltasten und per Wischen, grosse Schrift für den Beamer, eine Folie pro Gedanke, wenig Text.

Alles in einer Datei: kein Internet nötig, keine fremden Schriften oder Bibliotheken. Muss auf dem Handy (360 px breit) funktionieren.
Animation 
Erstelle eine Animation als einzelne HTML-Datei, die zeigt, wie ⟪z. B. ein Wurf in der Luft eine Parabel beschreibt⟫. Mit Start, Pause und Zurück, dazu ein Regler für ⟪Abwurfwinkel⟫. Beschrifte die Achsen.

Alles in einer Datei: kein Internet nötig, keine fremden Schriften oder Bibliotheken. Muss auf dem Handy (360 px breit) funktionieren.
Simulation 
Erstelle eine Simulation als einzelne HTML-Datei: ⟪ein Bungee-Sprung⟫. Regler für ⟪Masse, Seillänge, Federkonstante⟫. Links die Animation, rechts ein Diagramm ⟪Höhe gegen Zeit⟫, das mitläuft. Rechne mit den richtigen physikalischen Formeln und nenne sie unter der Grafik.

Alles in einer Datei: kein Internet nötig, keine fremden Schriften oder Bibliotheken. Muss auf dem Handy (360 px breit) funktionieren.
Trainer 
Erstelle einen Trainer als einzelne HTML-Datei für ⟪Einheiten umrechnen, z. B. km/h in m/s⟫. Er stellt zufällige Aufgaben, prüft meine Eingabe, gibt bei einem Fehler einen Tipp statt der Lösung und zählt die Punkte. Nach ⟪10⟫ Aufgaben zeigt er, welche ich falsch hatte.

Alles in einer Datei: kein Internet nötig, keine fremden Schriften oder Bibliotheken. Muss auf dem Handy (360 px breit) funktionieren.
A3Ausprobieren und nachbessern10–60 min

Claude zeigt das Ergebnis meist gleich in einer Vorschau neben dem Chat. Probiere es aus wie jemand, der es zum ersten Mal sieht. Dann beschreibe eine Sache, die stört, möglichst genau:

  • schwach: «Mach es schöner.»
  • gut: «Auf dem Handy ist der Regler zu klein zum Treffen. Mach ihn mindestens 44 px hoch.»
  • gut: «Bei Winkel 90° fliegt der Ball aus dem Bild. Die Achse soll mitwachsen.»
  • zum Verstehen: «Erkläre mir in einfachen Worten, wie der Teil funktioniert, der die Punkte zählt.»

Eine Sache pro Nachricht. Wird der Chat sehr lang und Claude vergisst Dinge: neuen Chat öffnen, die letzte Datei hineinziehen und sagen, woran du weiterarbeitest.

A4Speichern und öffnen2 min
  1. Datei herunterladen, sie endet auf .html. Gib ihr einen Namen ohne Leerzeichen und Umlaute, z. B. einheiten-trainer.html.
  2. Doppelklick öffnet sie im Browser, auch ohne Internet.
  3. Teilen geht schon jetzt: per Teams, Mail oder USB-Stick. Wer sie bekommt, braucht nur einen Browser.
A5Online stellen, ohne Terminal15 min

Damit dein Werk eine Adresse bekommt, die man mit dem Handy öffnen kann:

  1. Auf github.com ein Gratis-Konto anlegen. Der Benutzername wird Teil deiner Adresse.
  2. Oben rechts + → New repository. Name z. B. trainer, Public wählen, Create repository.
  3. Auf uploading an existing file klicken, deine Datei hineinziehen. Wichtig: Vorher in index.html umbenennen, dann ist sie die Startseite. Unten Commit changes.
  4. Settings → links Pages → bei Branch main und / (root) wählen → Save.
  5. Nach ein bis zwei Minuten ist sie online unter https://⟪benutzername⟫.github.io/trainer/.

Neue Fassung? Wieder Add file → Upload files, gleicher Name, und GitHub ersetzt die alte. Die alte bleibt in der Geschichte erhalten.

A6Mehrere Dateien: Cowork in der Desktop-AppWenn es grösser wird

Wird aus einer Datei ein kleines Projekt mit Bildern, mehreren Seiten oder Daten, hilft die Claude-Desktop-App (Windows, Mac) mit dem Modus Cowork:

  1. App von claude.ai/download installieren und anmelden.
  2. Einen leeren Ordner anlegen, z. B. Dokumente/meine-praesentation, und ihn in Cowork freigeben.
  3. Claude legt die Dateien direkt in diesem Ordner an und ändert sie dort. Es gibt kein Herunterladen und kein ZIP mehr.
  4. Zum Online-Stellen den ganzen Inhalt des Ordners wie in A5 hochladen.

Cowork ist der Zwischenschritt zwischen Weg A und B: Claude arbeitet in deinen Dateien wie in der Werkstatt, aber ohne Terminal. Was dir dann noch fehlt, ist die Geschichte jeder Änderung, also Git (Weg B). Die Funktionen der App ändern sich schnell; massgebend ist, was sie dir anzeigt.

Ebene 3 · Weg BDie Werkstatt: so wie begreifbar entsteht

Einmal einrichten (B1–B5), dann immer gleich arbeiten (B6–B7). B8–B10 sind das, was begreifbar über die Monate dazugelernt hat. Nimm sie dazu, wenn du sie brauchst.

B1Ubuntu installieren (Windows)30 min

Die Werkzeuge der Werkstatt sind für Linux gebaut. Windows bringt ein echtes Ubuntu mit, «WSL» genannt. Auf dem Mac überspringst du diesen Schritt und nimmst das Programm Terminal.

  1. Startmenü → «PowerShell» tippen → Rechtsklick → Als Administrator ausführen.
  2. Diesen Befehl eingeben, Enter:
PowerShell (Administrator) 
wsl --install
  1. Computer neu starten. Danach öffnet sich Ubuntu von selbst, sonst im Startmenü «Ubuntu» suchen.
  2. Einen Benutzernamen (klein, ohne Leerzeichen) und ein Passwort wählen. Beim Tippen des Passworts sieht man nichts, das ist normal.
Wo deine Dateien liegen Arbeite im Ubuntu-Ordner (~, also /home/⟪name⟫), nicht unter /mnt/c/…: Dort ist alles viel langsamer. Im Windows-Explorer findest du den Ubuntu-Ordner links unter Linux.
B2Die Werkzeuge installieren15 min

Fünf Programme: git (Geschichte), python3 und node (für Skripte), gh (Verbindung zu GitHub) und Claude Code. Am einfachsten mit dem Einrichtungsskript, das alles nacheinander erledigt und nachfragt:

Ubuntu-Terminal 
curl -fsSLO https://begreifbar.ch/projektwoche/werkstatt/einrichten.sh
less einrichten.sh     # zuerst lesen, was es tut (Ende mit q)
bash einrichten.sh

Oder von Hand, Zeile für Zeile:

sudo apt update
sudo apt install -y git python3 nodejs npm gh curl unzip
curl -fsSL https://claude.ai/install.sh | bash
git config --global user.name "⟪Vorname Name⟫"
git config --global user.email "⟪deine@mail.ch⟫"
git config --global init.defaultBranch main

Prüfen: Terminal schliessen, neu öffnen, claude --version. Erscheint eine Nummer, ist alles da.

Gewohnheit: Ein Skript aus dem Internet erst lesen, dann ausführen. Das gilt auch für dieses.

B3GitHub-Konto verbinden5 min

Konto auf github.com anlegen, falls noch nicht geschehen. Dann im Terminal (das Einrichtungsskript macht das schon):

gh auth login

Wählen: GitHub.com → HTTPS → Login with a web browser. Den angezeigten Code im Browser eintippen. Danach fragt Git nie mehr nach einem Passwort.

B4Das erste Projekt15 min

Ein Ordner für das Projekt, Git einschalten, Claude starten:

mkdir -p ~/meine-seite
cd ~/meine-seite
git init
claude

Beim ersten Start meldest du dich im Browser an. Claude Code braucht ein bezahltes Abo, der Gratis-Plan schaltet es nicht frei. Dann tippst du deinen Auftrag, so wie im Chat:

Lege eine Website an: index.html als Startseite über ⟪Thema⟫, eine style.css für das ganze Aussehen. Schweizer Rechtschreibung, keine Dateien von fremden Servern, funktioniert auf dem Handy.

Claude fragt, bevor es Dateien anlegt oder Befehle ausführt. Lies, was es vorhat, und bestätige. Danach, in einem zweiten Terminal-Fenster im selben Ordner:

git add -A
git commit -m "Erste Fassung"
gh repo create meine-seite --public --source=. --push

Der letzte Befehl legt das Repo auf GitHub an und lädt alles hoch.

B5GitHub Pages einschalten5 min
  1. Auf github.com dein Repo öffnen → Settings → Pages.
  2. Source: Deploy from a branch, Branch: main, Ordner / (root) → Save.
  3. Nach ein bis zwei Minuten: https://⟪benutzername⟫.github.io/meine-seite/.

Ab jetzt gilt: Jedes git push stellt die neue Fassung online. Was nicht gepusht ist, bleibt auf deinem Laptop.

Seite zeigt «404»? index.html muss zuoberst im Repo liegen, nicht in einem Unterordner.

B6Der Arbeitsrhythmus: drei Fenstertäglich

So arbeite ich an begreifbar, jeden Tag gleich. Drei Terminal-Tabs, alle im Projektordner (neuer Tab in Ubuntu: Ctrl+Shift+T):

Tab 1 · Claude Code: Aufträge 
claude
Tab 2 · Vorschau: die Seite im Browser 
python3 -m http.server

Dann im Browser http://localhost:8000 öffnen. Nach jeder Änderung F5.

Tab 3 · Git: sichern und veröffentlichen 
git status                        # was hat sich geändert?
git add -A                        # alles für den nächsten Commit vormerken
git commit -m "Trainer: Tipps bei falscher Einheit"
git push                          # erst wenn du zufrieden bist

Der Rhythmus: ein Auftrag → im Browser prüfen → committen. Kleine Schritte. Ein Commit ist ein Speicherpunkt, zu dem du jederzeit zurückkannst. Claude kann auch selbst committen, wenn du es darum bittest; den git push machst du selbst.

B7Regeln für Claude: die CLAUDE.md20 min

Claude Code liest bei jedem Start die Datei CLAUDE.md im Projektordner. Was dort steht, musst du nie wieder sagen. Lade die Vorlage herunter, speichere sie als CLAUDE.md in deinem Projekt und passe sie an. Oder lass Claude sie schreiben:

Schreibe eine CLAUDE.md für dieses Projekt: worum es geht, für wen, Sprache, wie die Dateien aufgebaut sind und welche Regeln gelten. Halte sie kurz. Frag mich, was du nicht weisst.

Die wichtigste Gewohnheit: Sagst du Claude etwas zum zweiten Mal, gehört es in die CLAUDE.md. So wurde die Hausordnung von begreifbar in fünf Monaten gross, eine Erfahrung nach der anderen.

B8Ein Aussehen, ein Prüfskriptwenn es mehr als drei Seiten sind

Eine CSS-Datei für alles. Farben, Schriften und Abstände stehen einmal in style.css. Neue Seiten übernehmen sie. So sieht Seite 50 aus wie Seite 1, und eine neue Farbe änderst du an einer Stelle.

Ein Prüfskript statt Nachschauen. Bei vielen Seiten übersiehst du Fehler. Lass Claude ein Skript schreiben, das sie findet:

Schreibe ein Python-Skript pruefen.py, das alle HTML-Seiten prüft: kaputte Links, fehlende Bilder, Seiten ohne Titel, Dateien von fremden Servern. Am Ende eine Zeile «ALLE CHECKS BESTANDEN» oder die Liste der Fehler. Trag in die CLAUDE.md ein, dass es vor jedem Commit läuft.

Bei begreifbar heisst dieses Skript «Pre-Flight», wie die Kontrolle vor dem Start eines Flugzeugs. Es ist mit der Zeit auf viele Prüfungen gewachsen: Formeln, Animationen, Barrierefreiheit, Breite auf dem Handy.

Skripte statt Handarbeit. Was sich wiederholt, macht ein Skript: das Inhaltsverzeichnis, die Suche, die Fusszeile. Du sagst Claude, was du willst, und Claude schreibt das Skript.

B9Eine eigene Adressefreiwillig, kostet etwas
  1. Domain bei einem Anbieter kaufen (für .ch rund 10 bis 20 Franken im Jahr).
  2. Beim Anbieter die DNS-Einträge setzen. Für eine Unteradresse wie mathe.begreifbar.ch: ein CNAME auf ⟪benutzername⟫.github.io. Für die Hauptadresse: vier A-Einträge auf 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153.
  3. Im Repo: Settings → Pages → Custom domain eintragen. GitHub legt eine Datei CNAME an.
  4. Warten, bis das Zertifikat da ist (bis 24 Stunden), dann Enforce HTTPS anhaken.

Die Aufzeichnungen dazu stehen im README der Startseite.

B10Vertonte, animierte Clipsfür Fortgeschrittene

So funktionieren die Clips von begreifbar, im Prinzip:

  1. Drehbuch: Eine Textdatei (JSON) sagt Szene für Szene, was erscheint und was gesprochen wird. Nur sie schreibe ich (mit Claude).
  2. Bild: Ein Python-Skript macht daraus eine kleine Webseite von rund 17 kB, die die Formeln Zeile für Zeile aufbaut. Kein Video, darum auf jedem Bildschirm scharf.
  3. Ton: Das Sprachprogramm Piper liest den Sprechertext mit der Stimme «Thorsten» vor, lokal und ohne Internet. Ein zweites Skript misst, wie lange jede Szene gesprochen wird, und passt die Animation an.
  4. Einbau: Ein drittes Skript hängt den Clip an die passenden Seiten und in die Bibliothek.
Piper installieren 
python3 -m venv ~/piper-venv
~/piper-venv/bin/pip install piper-tts soundfile

Die Stimme gibt es unter rhasspy/piper-voices → de/de_DE/thorsten/high (rund 109 MB). Die ganze Anleitung mit allen Feldern des Drehbuchs: HOWTO-clips.md. Für den Einstieg reicht ein Auftrag an Claude Code: «Baue mir ein System für kurze animierte Erklärclips nach dem Vorbild von begreifbar: Drehbuch als JSON, Ausgabe als HTML, Ton mit Piper.»

Zum NachschlagenGit auf einer Seite

BefehlWas er tut
git statusZeigt, was sich seit dem letzten Commit geändert hat. Im Zweifel immer zuerst.
git diffZeigt die Änderungen Zeile für Zeile (Ende mit q).
git add -AMerkt alle Änderungen für den nächsten Commit vor.
git commit -m "…"Speicherpunkt mit Beschreibung. Sag, was sich geändert hat.
git pushLädt die Commits auf GitHub; mit Pages geht die Seite damit online.
git log --onelineDie Geschichte, ein Commit pro Zeile.
git restore ⟪datei⟫Verwirft ungesicherte Änderungen an einer Datei. Endgültig.
git pullHolt Änderungen von GitHub, z. B. wenn du an zwei Computern arbeitest.

Wenn etwas schiefgeht

«command not found»

Das Programm ist nicht installiert oder das Terminal kennt es noch nicht. Terminal schliessen und neu öffnen; hilft das nicht, Schritt B2 wiederholen. Bei Claude Code hilft claude doctor.

Die Seite online zeigt die alte Fassung

Ist gepusht? git status sagt es («Your branch is ahead» heisst: noch nicht). Dann ein bis zwei Minuten warten und im Browser Ctrl+F5 drücken. Unter Actions im Repo siehst du, ob GitHub noch baut.

«rejected» beim git push

Auf GitHub liegt etwas, das du lokal nicht hast, zum Beispiel eine Datei, die du im Browser hochgeladen hast. Zuerst git pull, dann wieder git push. Nie --force, wenn du nicht genau weisst, warum.

Claude hat etwas kaputt gemacht

Darum committest du oft. git diff zeigt, was sich geändert hat, und git restore ⟪datei⟫ holt den Stand des letzten Commits zurück. Oder sag Claude: «Mach die letzte Änderung rückgängig und erkläre, was schiefging.»
