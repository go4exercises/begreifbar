In fünf MinutenDie Woche auf einen Blick

Vier Tage, eine eigene Idee, ein fertiges Produkt im Netz: gebaut mit KI als Werkzeug, ohne Programmierkenntnisse. Am Freitag hat dein Produkt eine Adresse, die du weitergeben kannst, und es bleibt dir.

  1. DI 30.03.Erste Fassung im NetzIdee eingrenzen, erster Auftrag an die KI, testen, online stellen.
  2. MI 31.03.Verlässlich machenNachprüfen, Fehler finden, Regeln aufschreiben, Daten behalten.
  3. DO 01.04.Gut machenGestaltung, Quellen, Blindtest mit anderen, Schlusscheck.
  4. FR 02.04.VernissageAm Vormittag zeigst du dein Produkt. Am Nachmittag: Auswertung.

Dazu kommt ein Halbtag auswärts: ein Betriebsbesuch in der Region. Was an welchem Tag dazukommt, steht ausführlich in den zwölf Kursthemen.

Am Ende der Woche kannst du …
  • deine Idee so genau beschreiben, dass daraus eine funktionierende Anwendung entsteht,
  • Ergebnisse einer KI prüfen, Fehler erkennen und gezielt nachbessern,
  • dein Produkt veröffentlichen und einem Publikum vorstellen.

Was dein Produkt sein darf

Möglich Alles, was im Browser läuft, auf dem Laptop und auf dem Handy: ein Rechner für deinen Beruf, ein Prüfungstrainer, eine Lernkartei, ein kleines Spiel, eine Simulation, eine Seite, die zeigt, was du kannst.
Nicht möglich Benutzerkonten und Login · Datenbank auf einem Server · Bezahlfunktion, Shop · Personendaten von Dritten. Der Grund ist rechtlich, nicht technisch. Wer eine «App fürs Handy» will, bekommt eine Webseite, die auf dem Handy gut läuft: sofort teilbar, ohne Store.

Unsicher, ob deine Idee passt? Genau dafür ist der Kick-off da. Frag, wir finden eine Fassung, die geht.

Bis zur ProjektwocheDein Vorbereitungsauftrag

Vier Aufgaben. Die ersten zwei beginnen wir gemeinsam am Kick-off. Wer vorbereitet kommt, baut am Dienstag um 09:15 schon am eigenen Produkt.

Abgabe bis ⟪Datum⟫ via Teams, drei Dinge:
  1. die Adresse deiner Testseite (Aufgabe 2),
  2. deine gewählte Arbeitsweise (Aufgabe 3),
  3. dein Ideenblatt (Aufgabe 4).
Fragen jederzeit im Teams-Kanal. Du bekommst eine Rückmeldung zu deiner Idee vor der Woche.
1Claude-Konto einrichtengratis beginnen, Pro erst kurz vor der Woche10 min
  1. Auf claude.ai ein Konto anlegen. Nimm eine private E-Mail-Adresse: Dein Produkt bleibt dir auch nach der Schule.
  2. Die Claude-Desktop-App installieren: claude.ai/download (Windows oder Mac) und dich anmelden.
  3. Ausprobieren, mit dem Gratis-Konto: Bitte Claude um eine kleine Seite.
Erster Versuch, zum Kopieren 
Erstelle eine persönliche Visitenkarte als einzelne HTML-Datei: mein Vorname, mein Beruf, drei Dinge, die ich gerne mache. Schlicht, gut lesbar auf dem Handy, keine Dateien von fremden Servern.
  1. Claude Pro (rund CHF 25 pro Monat) erst ab ⟪Datum, ca. eine Woche vor der Projektwoche⟫ abschliessen. Der Monat deckt dann die Vorbereitung und die ganze Woche. Arbeitsweise B und C (Aufgabe 3) brauchen Pro.
  2. Erinnerung in den Kalender: nach der Woche kündigen, falls du nicht weitermachen willst.
Alter Claude setzt nach den Nutzungsbedingungen von Anthropic 18 Jahre voraus. Bist du jünger, melde dich vor dem Kick-off bei mir. Wir klären das gemeinsam.

Du bist in der Desktop-App angemeldet und hast deine Visitenkarte als .html-Datei gespeichert.

2GitHub-Konto und erstes Repodeine Visitenkarte geht online20 min

GitHub bewahrt dein Projekt auf und stellt es gratis ins Netz. Diese Aufgabe probt die ganze Kette einmal mit der Visitenkarte, damit am Dienstag nichts mehr hakt.

  1. Auf github.com/signup ein Konto anlegen, wieder mit der privaten E-Mail-Adresse. Der Benutzername wird Teil deiner Adresse (⟪name⟫.github.io): kurz, ernst gemeint, ohne Jahrgang.
  2. Zwei-Faktor-Anmeldung einrichten, wenn GitHub danach fragt: eine Authenticator-App auf dem Handy bereithalten. Die Wiederherstellungscodes sicher ablegen.
  3. Oben rechts + → New repository. Name: visitenkarte, Public, Create repository.
  4. Deine Datei in index.html umbenennen. Dann auf uploading an existing file klicken, die Datei hineinziehen, Commit changes.
  5. Settings → Pages → Branch main, Ordner / (root) → Save.
  6. Nach ein bis zwei Minuten: https://⟪name⟫.github.io/visitenkarte/ auf dem Handy öffnen.
Öffentlich heisst öffentlich Alles im Repo kann jede und jeder lesen, auch frühere Fassungen. Auf die Visitenkarte gehören Vorname und Beruf, keine Adresse, keine Telefonnummer.

Deine Visitenkarte öffnet sich auf dem Handy unter deiner eigenen Adresse.

Ausführlicher: Werkstatt, Schritt A5.

3Arbeitsweise wählenCowork, Claude Code in der App oder Ubuntu15 min

In allen drei Arbeitsweisen arbeitet Claude direkt in einem Ordner auf deinem Laptop. Sie unterscheiden sich darin, wie viel Technik du siehst und selbst in der Hand hast. Alle drei führen zum selben Ziel. Wechseln ist auch während der Woche möglich.

A · EINFACH

Cowork in der Desktop-App

Du gibst Claude einen Ordner frei, Claude legt die Dateien dort an und ändert sie.
  • kein Terminal, kein Git
  • online stellen per Upload auf GitHub
  • Einrichten: nichts Zusätzliches

Für dich, wenn du dich ganz aufs Produkt konzentrieren willst.

B · MITTEL

Claude Code in der Desktop-App

Derselbe Claude Code wie im Terminal, aber mit Fenstern und Knöpfen. Claude kann für dich committen und pushen.
  • Git mit Geschichte und Rückgängig
  • online stellen mit git push
  • Einrichten: Git installieren

Für dich, wenn du sehen willst, wie Profis arbeiten, aber ohne Terminal.

C · WERKSTATT

Ubuntu und Claude Code im Terminal

So entsteht begreifbar.ch. Ein Linux unter Windows, Claude Code im Terminal, alle Werkzeuge zur Hand.
  • volle Kontrolle, eigene Skripte
  • Git und GitHub über Befehle
  • Einrichten: 30 bis 60 Minuten

Für dich, wenn dich Technik reizt und du Geduld mit Fehlermeldungen hast.

Vier Fragen helfen beim Entscheiden

  1. Hast du schon einmal Befehle in ein Terminal getippt? Nein, und du willst es auch nicht: A oder B.
  2. Willst du jede Fassung zurückholen können? Ja: B oder C. Bei A geht das nur über die Geschichte auf GitHub.
  3. Wie viel Zeit hast du vor der Woche zum Einrichten? Kaum: A. Eine Stunde: B. Einen Nachmittag: C.
  4. Arbeitest du zu zweit? Dann wählt ihr dieselbe Arbeitsweise, und Git (B oder C) lohnt sich besonders.

Unsicher? Nimm A. Am Kick-off zeige ich alle drei kurz. Die Funktionen der App ändern sich schnell: Massgebend ist, was sie dir anzeigt.

Du hast dich für A, B oder C entschieden und die Einrichtung dafür ausprobiert, mit Pro ab ⟪Datum⟫.

4Projektidee formulierenein Ideenblatt, eine halbe Seite30–60 min

Eine gute Idee ist klein genug für vier Tage und gross genug, dass sie jemandem nützt. Kopiere das Ideenblatt in ein Dokument und fülle es aus:

Ideenblatt 
IDEENBLATT · Projektwoche 2027

Titel:
Allein / zu zweit:  (mit wem?)
Arbeitsweise:       A / B / C

Die Idee in einem Satz:
Für wen?
Was hat diese Person davon?

MVP – die kleinste Fassung, die schon nützt:
Backlog – was dazukommt, wenn Zeit bleibt:
  1.
  2.
  3.
Wann ist es gut? (woran merkst du am Freitag, dass es funktioniert)
Woher kommen die Inhalte? (eigene, Quellen, Bilder)

Rahmen-Check:
  [ ] läuft im Browser, auf Laptop und Handy
  [ ] kein Login, keine Benutzerkonten
  [ ] keine Datenbank auf einem Server
  [ ] kein Shop, keine Bezahlfunktion
  [ ] keine Personendaten von Dritten

Beispiele

  • Lernkartei, die schwierige Karten öfter zeigt. MVP: zwanzig Karten zu einem Fach, «gewusst / nicht gewusst». Backlog: eigene Karten, Fortschritt speichern.
  • Rechner für deinen Beruf, z. B. Stoffverbrauch und Zuschnitt. MVP: eine Rechnung mit drei Eingaben. Backlog: Skizze, Varianten, Ausdruck.
  • Spiel: Paarsuche Begriff und Erklärung. MVP: acht Paare, ein Thema. Backlog: mehrere Themen, Zeitmessung.

Die Idee mit Claude schärfen

Lass dich befragen, statt dir etwas vorschlagen zu lassen. Die Idee bleibt deine:

Ich plane für eine Projektwoche ein kleines Produkt, das im Browser läuft, auf Laptop und Handy, ohne Login, Datenbank, Shop oder Personendaten von Dritten. Ich habe vier Tage und kann nicht programmieren; programmieren wirst du. Meine Idee: ⟪deine Idee in einem Satz⟫.

Stell mir nacheinander Fragen, immer nur eine, bis die Idee klar ist. Schlag mir danach ein MVP vor, das an einem Vormittag zu bauen ist, und ein Backlog. Sag mir ehrlich, wenn die Idee zu gross ist oder gegen die Rahmenbedingungen verstösst.

Dein Ideenblatt ist ausgefüllt, der Rahmen-Check hat fünf Häkchen, und das MVP passt in einen Satz.
